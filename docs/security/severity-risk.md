# Severity and Risk Classification

## Overview

This document describes the severity, risk scoring, verdict, impact, and legacy status classification currently implemented in the Inovix Security Engine.

The classifications documented here are based on the current implementation.

Severity, risk score, verdict, impact, and legacy status represent different parts of the security-analysis result and should not be treated as identical concepts.

---

**Finding Severity**

Each detection finding can have one of the following severity levels:

| Finding Severity | Risk Weight |
|---|---:|
| LOW | 20 |
| MEDIUM | 50 |
| HIGH | 80 |
| CRITICAL | 100 |

The current Security Engine calculates the risk score by adding the severity weights of all detected findings.

The final risk score is capped at 100.

**For example:**

```text
LOW finding       → 20 points
MEDIUM finding    → 50 points
HIGH finding      → 80 points
CRITICAL finding  → 100 points

Multiple findings can increase the total score, but the final score cannot exceed 100.

**Risk Score**

The current Security Engine produces a normalized risk score from:

0–100

The risk score is calculated from the severity weights of the detected findings.

If no findings are detected:

Risk Score = 0

If one or more findings are detected, their configured severity weights are added together and capped at 100.

**Example:**

URL_PRESENT              → LOW → 20
SUSPICIOUS_LANGUAGE      → MEDIUM → 50

Total Risk Score = 70

Another example:

CREDENTIAL_REQUEST       → HIGH → 80
URL_PRESENT              → LOW → 20

Total Risk Score = 100
Security Verdict

The current Security Engine generates one of three verdicts.

Risk Score	Verdict
0	SAFE
1–79	SUSPICIOUS
80–100	MALICIOUS
SAFE

A SAFE verdict is returned when no detection findings contribute to the risk score.

Risk Score = 0
Verdict = SAFE
SUSPICIOUS

A SUSPICIOUS verdict is returned when the risk score is greater than 0 but below 80.

Risk Score = 1–79
Verdict = SUSPICIOUS

This indicates that one or more security indicators were detected, but the current scoring logic did not reach the MALICIOUS threshold.

MALICIOUS

A MALICIOUS verdict is returned when the risk score is 80 or higher.

Risk Score = 80–100
Verdict = MALICIOUS

This represents the highest verdict level currently generated by the Security Engine.

Impact Assessment

The current Security Engine also generates a basic impact assessment.

Risk Score	Impact Level
0	LOW
1–79	MEDIUM
80–100	HIGH

The implemented impact assessment is currently based directly on the calculated risk score.

LOW Impact

Returned when:

Risk Score = 0

The result indicates that no security impact indicators were detected.

MEDIUM Impact

Returned when:

Risk Score = 1–79

The result indicates that detected security indicators require review.

HIGH Impact

Returned when:

Risk Score = 80–100

The result indicates that high-risk security findings were detected.

The current implementation does not generate a CRITICAL impact level.

Legacy Status Classification

For backward compatibility, the Security Engine also exposes a status value derived from the verdict and risk score.

The current logic is:

Verdict / Risk Score	Legacy Status
SAFE	SAFE
SUSPICIOUS with score below 50	LOW
SUSPICIOUS with score 50 or above	MEDIUM
MALICIOUS	HIGH
Unknown result	UNKNOWN

This legacy status should not be confused with finding severity or the primary security verdict.

The primary current verdict values are:

SAFE
SUSPICIOUS
MALICIOUS

Severity, Risk, Verdict, and Impact

The current Inovix implementation uses several related but distinct concepts.

Finding Severity

Describes the severity assigned to an individual detection finding.

Current values:

LOW
MEDIUM
HIGH
CRITICAL
Risk Score

Represents the calculated numerical score from all detected findings.

Current range:

0–100
Verdict

Represents the primary security classification generated from the risk score.

Current values:

SAFE
SUSPICIOUS
MALICIOUS
Impact

Represents the current basic impact assessment.

Current values:

LOW
MEDIUM
HIGH

These concepts should not be presented as interchangeable.

For example, a CRITICAL finding contributes 100 points to the risk score, but the final engine verdict is MALICIOUS rather than CRITICAL.

Classification Principles

The current implementation follows these principles:

Detection findings contribute to the overall risk score.
Multiple findings can increase the risk score.
The final risk score is capped at 100.
A risk score of 0 produces a SAFE verdict.
A risk score from 1 to 79 produces a SUSPICIOUS verdict.
A risk score from 80 to 100 produces a MALICIOUS verdict.
Finding severity is separate from the final verdict.
Impact assessment is separate from finding severity.
The legacy status value exists for backward compatibility.

A detection result should not automatically be interpreted as proof of malicious activity beyond what the implemented rule-based logic supports.

Implementation Status

The following functionality is currently implemented in the Security Engine:

Finding severity classification
Severity-based risk weights
Risk score calculation
Risk score normalization to a maximum of 100
SAFE, SUSPICIOUS, and MALICIOUS verdict generation
Basic LOW, MEDIUM, and HIGH impact assessment
Backward-compatible status classification

The exact scoring methodology may be expanded or changed as the Security Engine evolves.

Any future changes to severity weights, verdict thresholds, impact logic, or classification behavior should be verified against the implementation before this document is updated.
