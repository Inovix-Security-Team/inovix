# Inovix Demo Flow

## Overview

This document describes the controlled demonstration flow for the Inovix MVP.

The demo uses safe and synthetic security events to demonstrate how security information can move through the Inovix workflow.

Only functionality confirmed by the implementation should be presented as implemented. Planned or unconfirmed functionality remains clearly identified.

---

## Demo Objective

The demonstration should show how a controlled security event can move through the Inovix security workflow.

The intended end-to-end flow is:

1. Start Inovix
2. Generate a safe synthetic event
3. Event enters Inovix
4. Normalize the event
5. Detect suspicious activity
6. Apply anomaly scoring where implemented
7. Apply threat-intelligence enrichment where implemented
8. Correlate related events where implemented
9. Calculate risk
10. Create an incident where implemented
11. Simulate or perform the supported response
12. Verify the result
13. Display the relevant information in the SOC or dashboard

Components that are not yet implemented must remain marked as planned or TBD.

## Normal Activity Scenario

A normal event is also included in the demonstration.

Expected flow:

Normal Event
↓
Analysis
↓
No Significant Detection
↓
No Unnecessary Incident

This scenario demonstrates that Inovix should not classify every event as malicious without sufficient evidence.

The final behavior must match the implemented detection and incident logic.

## Safety

All demonstration scenarios must follow these rules:

- Use synthetic or authorized test data.
- Do not attack or scan unauthorized systems.
- Do not use real stolen credentials.
- Do not execute malware.
- Do not expose secrets.
- Do not claim successful prevention or blocking unless it has been verified.
- Clearly distinguish simulated behavior from implemented behavior.
